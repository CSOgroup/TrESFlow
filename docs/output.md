# TrESFlow: Output

## Overview

`TrESFlow` writes modality-specific outputs directly under `--outdir`.
The exact directories present depend on whether the YAML samplesheet contains `rna`, `dna`, or both modalities.

## Top-level result directories

RNA-related outputs:

- `rna_split_fastqs/` when `--publish_split_fastqs` is enabled
- `rna_align/`
- `TrES_Stats/`

DNA-related outputs:

- `dna_split_fastqs/` when `--publish_split_fastqs` is enabled
- `dna_align/`
- `TrES_Stats/`

Shared reporting outputs:

- `pipeline_info/`
- `TrES_Stats/tres_report.html`
- `TrES_Stats/read_retention.tsv`
- `TrES_Stats/qc_metrics.tsv`
- `TrES_Stats/barcode_composition.tsv`
- `TrES_Stats/library_complexity.tsv`
- `TrES_Stats/qc/fastqc/`
- `TrES_Stats/qc/samtools/`
- `TrES_Stats/qc/multiqc/`

## RNA outputs

### Optional `rna_split_fastqs/`

Per-group RNA FASTQs from the split stage:

- `<sample>_<group>_R1.fastq.gz`
- `<sample>_<group>_R2.fastq.gz`

`SPLIT_RNA_READS` always writes plain FASTQs for `FQ_TO_SAM`. When
`--publish_split_fastqs` is enabled, a separate `pigz -c` branch creates the
files above without making alignment wait for publication compression. By
default the compression task does not run and this directory is absent. Plain
computational FASTQs and SAM read-group headers are never published.

### `rna_align/`

STARsolo and filtered BAM outputs:

- `<sample>_<group>.Solo.outGeneFull/`
- `<sample>_<group>.Log.final.out`
- `<sample>_<group>.filtered_cells.bam`
- `<sample>_<group>.stranded_*.bw`
- `<sample>_<group>.unstranded_*.bw`

The filtered BAM and both BigWig branches contain only the canonical human
chromosomes resolved from the STAR index. `RNA_FILTERED_BAM` publishes the
low-compression BAM directly; coverage and Samtools QC consume that same BAM
without a publication-only copy or recompression stage.

## DNA outputs

### Optional `dna_split_fastqs/`

Per-group and per-mark DNA split FASTQs:

- `<sample>_<group>_<mark>_R1.fastq.gz`
- `<sample>_<group>_<mark>_R2.fastq.gz`

`SPLIT_DNA_READS` always writes plain FASTQs for `ALIGN_DNA`. When
`--publish_split_fastqs` is enabled, a separate `pigz -c` branch creates the
files above in parallel with alignment. By default the compression task does
not run and this directory is absent. Plain computational FASTQs and SAM
read-group headers are never published.

### `dna_align/`

Duplicate-marked BAMs, final duplicate-filtered BAMs, and coverage tracks:

- `<sample>_<group>_<mark>_MarkedDup.bam`
- `<sample>_<group>_<mark>_MarkedDup.bam.bai`
- `<sample>_<group>_<mark>.DuplicateMetrics.txt`
- `<sample>_<group>_<mark>_NoDup.bam`
- `<sample>_<group>_<mark>_NoDup.bam.bai`
- `<sample>_<group>_<mark>_NoDup.bw`

`*_MarkedDup.bam` is generated by nf-core `gatk4/markduplicates` with TrESFlow's barcode-aware duplicate settings. The published `*.DuplicateMetrics.txt` is Picard's machine-readable metrics table and includes `READ_PAIRS_EXAMINED`, `READ_PAIR_DUPLICATES`, `READ_PAIR_OPTICAL_DUPLICATES`, `PERCENT_DUPLICATION`, and `ESTIMATED_LIBRARY_SIZE`; the latter is TrESFlow's reported library-complexity estimate. These fields are also parsed into `TrES_Stats/qc_metrics.tsv` and `TrES_Stats/library_complexity.tsv`. Its normalized publication copy is then restricted to the canonical chromosomes resolved from the bwa-mem2 index. `SPLIT_DUPLICATES_DNA` removes only records carrying flag `0x400`, indexes the NoDup BAM, and counts its mapped reads; enabling optical classification changes Picard metrics but does not add another removal predicate. Canonical filtering is not repeated because its input already comes exclusively from `NORMALIZE_DNA_MARKDUPLICATES`. DNA QC always receives the original NoDup BAM and index. Nonempty NoDup BAMs flow directly to nf-core `deeptools/bamcoverage`, which writes `<sample>_<group>_<mark>_NoDup.bw` without a normalization or copy task. Zero-mapped BAMs skip coverage and publish `pipeline_info/warnings/*.zero_mapped_nodup_bam.tsv`.

## Tagging/count/stat outputs

### `TrES_Stats/`

Tagging summaries are published with modality-specific names:

- `<sample>.rna_sample_barcode.counts.tsv`
- `<sample>.rna_sample_barcode.stats.tsv`
- `<sample>.rna_umi.counts.tsv`
- `<sample>.rna_cell.counts.tsv`
- `<sample>.rna_cell.stats_L1.tsv`
- `<sample>.rna_cell.stats_L2.tsv`
- `<sample>.rna_cell.stats_L3.tsv`
- `<sample>.rna_tag_records.tsv.gz`
- `<sample>.dna_sample_barcode.counts.tsv`
- `<sample>.dna_sample_barcode.stats.tsv`
- `<sample>.dna_modality.counts.tsv`
- `<sample>.dna_modality.stats.tsv`
- `<sample>.dna_cell.counts.tsv`
- `<sample>.dna_cell.stats_L1.tsv`
- `<sample>.dna_cell.stats_L2.tsv`
- `<sample>.dna_cell.stats_L3.tsv`
- `<sample>.dna_tag_records.tsv.gz`
- `<sample>.dual_tag_artifact_filter.cutadapt.json` for filtered dual-tag samples
- `<sample>.dual_tag_artifact_filter.summary.tsv` for filtered dual-tag samples

Tag-record tables are emitted only as final gzip artifacts; no complete uncompressed tag-record copy is retained.

The dual-tag artifact summary reports input, retained, and rejected read-pair
counts; per-mate signature counts; Cutadapt version; and the audited signature
FASTA SHA-256. Here, `input_pairs` means pairs that survived the preceding Trim
Galore step, not the original raw or pre-trimming pair count. Its accounting is
validated as `input_pairs = retained_pairs + rejected_pairs`. The raw Cutadapt
JSON and summary TSV are also supplied to the shared report/QC collection. No
rejected or transient cleaned FASTQs are published. These files are absent for
single-tagmentation samples and when `--filter_dual_tag_artifacts false`.

### Read-retention counters in `TrES_Stats/`

The pipeline publishes small TSV counters for reconstructing nested read-pair
populations without rereading the large FASTQ and transient BAM files:

- `<sample>.rna_read_retention.tsv`
- `<sample>.rna_barcode_gates.tsv`
- `<sample>.rna_barcode_composition.tsv`
- `<sample>_<group>.rna_filter_retention.tsv`
- `<sample>.dna_read_retention.tsv`
- `<sample>.dna_barcode_gates.tsv`
- `<sample>.dna_barcode_composition.tsv`
- `<sample>_<group>_<mark>.dna_alignment_retention.tsv`

The RNA and DNA split tables are written by the same Codon loop that emits the
computational FASTQs. `split_input_pairs` means pairs entering that loop. It is
the paired Trim Galore population for RNA, single-tag DNA, and dual-tag DNA with
artifact filtering disabled; for filtered dual-tag DNA it is the post-artifact-
filter population. The tables retain the historical
`joint_barcode_accepted_pairs` count and exact group/mark routing counts.

The `*_barcode_gates.tsv` sidecars intersect the QNAMEs entering splitting with
the barcode decisions already recorded by `Tag_Lig3`; they do not rerun barcode
matching. Their cumulative counts are therefore exact same-pair populations.
RNA reports `split_input_pairs`, all-three-ligation-barcode acceptance, then
sample-barcode acceptance. DNA adds MO-barcode acceptance. Every gate uses
`split_input_pairs` as its documented denominator, and every successive gate is
validated as a subset of its predecessor.

The upstream `*_barcode_composition.tsv` sidecars contain mutually exclusive categories,
including an explicit `NoMatch` row even when its count is zero. Sample rows
include `barcode_sequence` and `barcode_label`, and retain the configured group;
the sequence is the existing corrected tag decision, not a rematched sequence.
Sample-barcode rows in those upstream sidecars use the all-L1/L2/L3-accepted population as their denominator. DNA
mark composition is kept separately per configured sample-barcode group/run and
uses that group's sample-barcode-accepted population as its denominator. Each
category set is validated to sum exactly to its denominator. The older barcode
statistics listed above remain useful marginal diagnostics against raw input,
but are not conditional retention stages.

For the report's sequence-level sample-barcode visualization and consolidated
`barcode_composition.tsv`, assigned counts come from the matching
`*_sample_barcode.counts.tsv`; `NoMatch` comes from `reads_without_bc` in
`*_sample_barcode.stats.tsv`. The reader validates the counts-file NoMatch row
when present, assigned sum against `bc_reads`, and assigned plus NoMatch against
`reads`. The denominator is therefore all pairs evaluated by that sample-
barcode tagger, not the cumulative L1/L2/L3 gate.

The DNA alignment table reports nested primary-R1 pair representatives after
BWA, blacklist removal, mapped-record selection, and the existing proper-pair
filter. The RNA filter table reports nested primary-R1 pair representatives
after STAR mapping, the existing paired-flag filter, canonical-chromosome
selection, and called-cell selection. One primary R1 record is the stable
representative for one input pair, preventing secondary or supplementary
alignments from being counted as additional fragments. These files are metrics
only and do not alter the FASTQ or BAM data path.

## QC and HTML reports

### `TrES_Stats/qc/fastqc/`

nf-core `fastqc` writes raw FASTQ QC files:

- `*_fastqc.html`
- `*_fastqc.zip`

### `TrES_Stats/qc/samtools/`

When real BAMs are produced, one combined Samtools QC task per BAM writes:

- `*.flagstat`
- `*.stats`
- `*.idxstats`
- `*.quickcheck.tsv`

The combined task reads existing RNA filtered BAMs and DNA aligned / marked-duplicate / NoDup BAMs. It runs flagstat, stats, quickcheck, and DNA-only idxstats without modifying any downstream TrESFlow outputs.

In `-profile test`, the samtools sidecars are disabled because the smoke profile intentionally uses lightweight mock BAM text files.

### `TrES_Stats/qc/multiqc/`

nf-core `multiqc` writes:

- `multiqc_report.html`
- `multiqc_report_data/`

MultiQC aggregates supported logs and QC text files, including FastQC, STAR logs, samtools outputs, and GATK duplicate metrics when present.

### TrESFlow report files in `TrES_Stats/`

The TrESFlow-specific end-of-run report writes directly into `TrES_Stats/`:

- `tres_report.html`
- `read_retention.tsv`
- `qc_metrics.tsv`
- `barcode_composition.tsv`
- `library_complexity.tsv`

This custom report is separate from MultiQC and needs no network resources. The
pipeline process and `bin/assess_tresflow_run.py` share the same parsers,
reconciliation rules, normalized model, plotting functions, and HTML renderer.
The concise report presents independent-run overview cards and one applicable
figure per independent run for exact retention, DNA marks, sample barcodes,
observed DNA duplicate complexity, actual Picard ROI points, and STARsolo RNA
sequencing saturation. Every plot is responsive inline SVG with data-derived
dimensions, measured-width label placement, deterministic scalable category
colours, and browser-side SVG and PNG download controls. Sample-barcode segments
contain no text; every configured category, including zero-count categories, is
identified in an adaptive external value key and retained in the exact table.
The report title is the resolved root output-directory basename, overview-card
titles use samplesheet groups, and the displayed pipeline version is the exact
checkout release tag or a deterministic nearest-release development baseline.
A source archive without Git metadata falls back to the release-baseline value
in `nextflow.config`'s `manifest.version`, then to `unreleased` if that metadata
is absent or invalid.
The pipeline report task
leaves no separate JSON, PNG, or SVG artifact and omits only the optional
figures whose authoritative inputs do not exist.

RNA sequencing saturation is read directly from STARsolo
`Solo.outGeneFull/Summary.csv`. For STAR 2.7.11b it is
`1 - collapsed UMIs / reads assigned to a unique GeneFull feature`; TrESFlow
does not derive it from retention counts or label it as an absolute RNA
duplicate count. DNA duplicate percentages use Picard `READ_PAIRS_EXAMINED`;
PCR/library and optical numerators are summed across marks before a run-level
percentage is calculated.
For legacy outputs, only stages supported by retained exact files are shown;
missing cumulative gates are never estimated from marginal percentages.

## Pipeline information

`pipeline_info/` contains execution metadata and the derived helper contract written from the YAML samplesheet.

Expected files include:

- `execution_report.html`
- `execution_timeline.html`
- `execution_trace.tsv`
- `flowchart.html`
- `runtime_contract.tsv`
- `warnings/*.zero_mapped_nodup_bam.tsv` when DNA NoDup BAMs have zero mapped reads and bamCoverage is skipped

When the YAML contains group and DNA mark definitions, the parser also writes:

```text
pipeline_info/derived_contract/
```

with files such as:

- `sb_group_map.tsv`
- `dna_mo_map.tsv`
- per-sample DNA modality whitelist files

## FASTQ retention policy

The pipeline does not keep intermediate tagging, uSAM, duplicate-split, or coverage side products in the published results.

- with `--publish_split_fastqs`, published RNA FASTQs are the grouped split FASTQs under `rna_split_fastqs/`
- with `--publish_split_fastqs`, published DNA FASTQs are the grouped and marked split FASTQs under `dna_split_fastqs/`
- split FASTQ publication defaults to disabled, so neither directory nor its publication-only compression work is created unless requested
- earlier tag, trim, RNA uSAM, STAR aligned BAM, tag-record, and non-published coverage side products are transient task outputs
- split FASTQs are uncompressed only on internal computational channels; the published copies remain gzip-compressed
- RNA coverage, QC, and publication all consume the same low-compression `RNA_FILTERED_BAM` output under `rna_align/*.filtered_cells.bam`
- DNA duplicate-marked BAMs are published under `dna_align/` as duplicate-aware alignment outputs

By default, `--cleanup_work true` asks Nextflow to clean successful task work directories after the workflow finishes successfully. This preserves published outputs while reducing retained `work/` storage. Set `--cleanup_work false` to keep work directories for debugging or a more resume-friendly run.
